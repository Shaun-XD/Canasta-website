# Android release QA

The [final installed build](#final-package-5d6188c) was made from commit `5d6188c`. The foldable-emulator results, production multiplayer tests and device recording below identify the tested artifact. Earlier candidates document the defects found and corrected during release QA.

The baseline was run on 19 November 2026 (Hong Kong time) in a `git archive` of `6bc63af0066e54b7f821a5f43ee3826fc280c4cd`, prior to Android integration. `npm run lint`, `tsc -b`, `npm run build`, and `npm test` passed (245 tests, 18 suites). `baseline.log` contains the tool output. The tests include the Node TypeScript game bridge.

## Supplemental website and service checks

`browser-viewport-baseline.jsonl` covers four Chromium viewport profiles against the public website. The shipped layout deliberately gives larger controls to spacious handhelds, including the unfolded OnePlus. The desktop profile of identical width does not get that mode. A separate simulated 844×390 phone successfully tapped the opening discard and selected a card with touch. These runs are viewport simulations.

`backend-live-baseline.json` covers isolated 4-client WebSocket play on the live Railway backend, including room capacity, 2/4 player settings, bots, ready/start, synchronized turns, pause and rejoin. `score-live-baseline.json` records two synthetic clients completing 64 ordinary draw/discard turns, ending the round with an exhausted stock and starting round 2 with the same cumulative scores. These service checks are supplemental to an installed Android test.

## Android test environment

Android Studio's ARM64 API 36 Google Play system image runs in a private, cold-booted `CanastaOpen` AVD. The emulator uses the system image's Pixel 9 Pro Fold hinge/display-state profile and configured OnePlus Open screen dimensions (2268×2440 inside, 1116×2484 cover, 440 dpi). `adb emu fold` changes the emulated hinge angle to 0°, Android DeviceStateManager commits CLOSED, and WindowManager switches the default display to the actual smaller cover. `adb emu unfold` reverses this. This exercises Android configuration/display transitions separately from browser resizing. No physical Android or OnePlus device was connected. The guest is a clean test environment with no personal Google account.

The first candidate (`476dd9a`) installed cold from its unsigned release AAB with bundletool 1.18.3 universal output. Only the locally installed APK has the pre-existing Android debug certificate. The emulator used Android System WebView 133.0.6943.137. On the opened display, a fresh solo game showed a Joker opening discard. Two native taps selected the six of clubs and six of spades, and Meld Top created the team’s first meld. The discard pile became empty, the player’s hand shrank by two, the stock stayed at 59, and the UI continued in the action phase. A packaged host then created a production 1v1 room, and a separate Socket.IO client entered the room by code, readied, and synchronized the start. Later release-candidate results are recorded separately. QA screenshots use synthetic names. Room-code areas are masked in the retained evidence.

## Recreate the foldable fixture

The exact public settings are preserved in `foldable-api36.ini`. On an ARM64 host with the licensed API 36 Google Play system image installed, create a fresh private AVD directory and copy that file as its `config.ini`. Use the normal AVD registration file in the same private home, with the absolute path to the new AVD directory. For example, run from the repository root with the Android SDK emulator on PATH:

```sh
export ANDROID_AVD_HOME="$(mktemp -d)"
mkdir "$ANDROID_AVD_HOME/CanastaOpen.avd"
cp release/qa/foldable-api36.ini "$ANDROID_AVD_HOME/CanastaOpen.avd/config.ini"
printf 'avd.ini.encoding=UTF-8\npath=%s/CanastaOpen.avd\ntarget=android-36\n' "$ANDROID_AVD_HOME" > "$ANDROID_AVD_HOME/CanastaOpen.ini"
emulator -avd CanastaOpen -no-snapshot -no-boot-anim -no-audio -gpu host -no-metrics
```

Use the new serial from `adb devices` for every following command. Save the initial room, seat, turn and hand privately before folding. `adb -s SERIAL emu fold` and `adb -s SERIAL emu unfold` change the Android device state. `adb -s SERIAL shell dumpsys device_state` and `adb -s SERIAL shell wm size` report the active posture and display. The test used `adb -s SERIAL shell wm user-rotation lock 0` for portrait and `1` for landscape. The accompanying acceleration was `0:9.81:0` for portrait and `-9.81:0:0` for landscape via `adb -s SERIAL emu sensor set acceleration VALUE`. Production smoke rooms use only synthetic identities.

On the a64a6f0 install, a second client also hosted and Android joined by code as a guest. Both readied, started and completed turns. The native Android Back button closed an open table menu, displayed a confirmation when leaving the game, kept the table after Cancel, and returned home after accepting.

## Final package 5d6188c

The final candidate came from clean commit `5d6188cc24d2323fc0820b20cdc9ba54e43647ea`, version 1.0.0 (1), package `io.github.shaunxd.canasta`. The AAB checksum is `3ca8f703375ef4a9812e2a02440a9d601e82c613a9a7df0635a97f6869be8004`. The universal APK used for fresh installation on the foldable emulator has checksum `ac1e74e3746b43567af5e481b98e501e3bc016a2306a222113a3a024867d1b40`. Both files are under `artifacts/android-release/5d6188c/`. Bundletool generated this APK from the named unsigned AAB; the APK has the local debug certificate. The previous candidate was uninstalled before installation. The first Android activity start reported COLD/ok in 6.689 seconds. This build has not been upload-signed or installed through Play.

After clearing its data with airplane mode enabled, this build started a fresh solo game offline and accepted the opening K♦ discard with the Q♦ and a wild 2♥ from the hand. The stock stayed at 59, the pile emptied and the player held 11 cards after melding. After the human discard, the solo opponent completed its turn and the human drew from stock. Evidence is under `artifacts/android-release/device/5d6188c/`.

A second synthetic client joined the packaged Android host’s production 1v1 room by code and both players readied and started. Active emulator hinge transitions and rotations on both displays preserved the same server room, player seat, 13 card faces and human turn. The small cover portrait showed the rotation gate. Rotating the cover to landscape restored play. The stock control measured 182 device pixels on inner portrait, 168 on inner landscape and 93 on cover landscape. The unfolded hand was touch-reordered without changing its contents. See `android-fold-5d6188c.json` for measured postures and WebView dimensions.

On the final package the peer observed the Android host’s first draw/discard and then completed its turn while Android was backgrounded. Android resumed on the correct turn 3. The test disabled Android’s radios and required both a visible reconnect banner and a peer-observed seat disconnect. After restoring the radios the app automatically rejoined with the original room, seat, 13 card faces and turn. The Android host drew and discarded again, and the peer confirmed its own turn 4.

On the same final APK, the Android host created a production 2v2 room. The other human explicitly selected Team Blue, leaving a teammate bot and an opponent bot. The host filled, removed and refilled the bots, readied, started, paused the timer for both clients, resumed it, and drew and discarded. The teammate bot then drew, made two separate melds and discarded, with intervals of 1.402, 1.402 and 1.401 seconds between actions. The opponent bot independently drew, melded twice and discarded, with intervals of 1.403, 1.402 and 1.401 seconds. Android regained control on turn 5. A native Android screen recording showed cards moving between seats, the meld area and the discard pile. At about 12.61–12.82 seconds the opposing bot’s 4♥ moved from the right seat to the pile. The emulator recording was variable-frame-rate and gives sampled visual evidence. The action intervals are server event timestamps. The screen capture and action timings are retained in [the redacted bot turns](installed-bot-turns.webp) and [the recorded event intervals](android-2v2-both-roles-5d6188c.json).

The final Android APK also entered a fresh 1v1 code provided by another host. Both players readied, the remote host started, the Android guest drew and discarded on turn 2, and the host received turn 3. Android Back closed the open table menu. Back again presented the leave-table prompt, Cancel preserved play, and accepting the subsequent prompt returned home. The disposable QA peer was closed and the foldable AVD shut down after the test.
